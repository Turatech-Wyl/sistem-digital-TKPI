Agent WhatsApp untuk pembayaran TK: apa yang bisa kita pakai?

Hasil eksplorasi Baileys, proyek open source pendukung, dan ide dari KatalogIn / Socioblast, disesuaikan dengan server kita (2 GB RAM, 2 core, tanpa Docker).

Kesimpulan singkat Baileys langsung + Next.js, tanpa gateway tambahan.

Server terlalu kecil untuk Evolution API atau Chatwoot. Baileys dipasang sebagai proses Node terpisah, terhubung ke aplikasi TK lewat database yang sama. Ide fitur diambil dari Socioblast (bot jawab otomatis + konfirmasi bayar).

Arsitektur yang diusulkan

Dua proses di server yang sama, satu database SQLite.

Apa yang bisa dijawab bot tanpa AI

Aturan sederhana berbasis kata kunci sudah cukup menutup sebagian besar pertanyaan pembayaran.

1Kenali pengirim

Nomor dicocokkan ke tabel orang tua. Tidak dikenal → teruskan ke TU, jangan balas otomatis.

2Baca niat

Kata kunci: "tagihan", "berapa", "sudah bayar", "rekening", "bukti", "cuti". Sisanya → TU.

3Jawab dari database

Status SPP anak, nominal, rekening sekolah, riwayat 3 bulan terakhir. Semua dari data yang TU input.

4Bukti transfer

Foto masuk → simpan, tandai "menunggu verifikasi", TU dapat notifikasi. Setelah TU centang, konfirmasi otomatis.

Ide dari KatalogIn & Socioblast

Keduanya produk komersial (Socioblast mulai Rp 299 rb/bulan). Polanya bisa kita tiru untuk konteks sekolah.

KatalogIn

Link "tap → chat sudah terisi"

KatalogIn membuat pelanggan cukup tap link, WhatsApp terbuka dengan pesan siap. Untuk kita: tiap tagihan punya link wa.me/62…?text= yang dikirim ke orang tua, dan tombol cadangan untuk TU.

KatalogIn

Link pembayaran di dalam chat

Nanti bisa kirim QRIS statis sekolah atau link Midtrans/Xendit di pesan pengingat, sehingga orang tua bayar tanpa transfer manual. Tahap lanjutan.

Socioblast

Bot 24 jam + konfirmasi otomatis

Socioblast menjawab pertanyaan dan mengonfirmasi pembayaran otomatis. Versi kita: bot aturan kata kunci, ditambah AI hanya untuk pesan yang tidak cocok aturan, itu pun opsional.

Socioblast

Dashboard CRM satu inbox

Semua percakapan orang tua tampil di dashboard TK, dengan label "dijawab bot" atau "perlu TU". Ini yang membuat forwarder tidak berantakan.

Socioblast

Multi-kanal

Socioblast juga Telegram. Untuk TK, WhatsApp saja cukup, tapi struktur inbox/outbox kita buat netral supaya kanal lain bisa ditambah.

Keduanya

Broadcast ke yang opt-in

Pengumuman sekolah (libur, kegiatan) dikirim ke orang tua yang sudah menyimpan nomor sekolah. Pola anti-ban: jeda acak, batch kecil, hanya kontak yang dikenal.

Aturan main supaya nomor tidak diblokir

Nomor khusus sekolahWhatsApp Business baru, bukan nomor pribadi. Pemanasan 1–2 minggu: chat manual dulu ke beberapa orang tua.
Hanya ke kontak yang kenalBot hanya mengirim ke nomor yang ada di data siswa dan sudah pernah membalas. Tidak ada cold message.
Jeda dan batas20–40 detik antar pesan, maksimal ±50 pesan per jam. Pengingat dijadwalkan pagi, bukan tengah malam.
Cadangan manualKalau sesi putus atau nomor kena pembatasan, tombol wa.me di dashboard tetap jalan. Baileys bukan API resmi; kalau nanti sekolah mau resmi, ganti ke WhatsApp Cloud API tanpa ubah aplikasi.

Urutan pengerjaan

Agent WA dibangun setelah data pembayaran ada, karena bot menjawab dari data itu.

Tahap 1Aplikasi TK: data siswa, tagihan, catat bayar, impor Excel. Tabel outbox/inbox sudah disiapkan sejak awal.
Tahap 2Agent Baileys: koneksi, QR di dashboard, kirim dari outbox dengan jeda, simpan inbox, reconnect otomatis. Pola dicontek dari WA-AKG.
Tahap 3Bot aturan: kenali nomor, jawab tagihan/rekening/riwayat, terima bukti transfer, teruskan sisanya ke TU. Konfirmasi otomatis setelah TU centang.
Tahap 4Pengingat terjadwal tanggal 1 dan 10, broadcast pengumuman, inbox percakapan di dashboard. Uji satu siklus SPP bersama TU.
OpsionalAI untuk pesan di luar aturan (Claude Haiku, hemat), QRIS/link bayar di pesan, portal orang tua ala pembayaran-spp.
